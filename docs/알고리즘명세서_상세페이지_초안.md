# 알고리즘 명세서 — 콘텐츠 아키텍트 (상세페이지·판매 정보·이미지) 초안 v0.1

작성 2026-10-04 · 강근우 · 대상 요구사항 R-003 (콘텐츠 아키텍트), R-000-05 (부분 재실행)

이 문서는 **코드에 구현된 그대로**를 적는다. 숫자와 규칙은 모두 레포 파일에서 확인할 수 있고, 각 절 끝에 근거 파일과 검증 테스트를 적었다. 산출물(한이음 알고리즘 명세서) 양식으로 옮길 때 이 문서를 원본으로 쓴다.

## 1. 개요

| 알고리즘 | 화면 | 입력 | 출력 | 실행 방식 | LLM |
|---|---|---|---|---|---|
| A1. 판매 정보 추천 | SEL-01-01 판매 정보 입력 | 상품 정보, 국가 | Shopee 카테고리·속성·옵션 1·2단·재고 제안 | 동기 (≤10초) | gpt-4o-mini 1회 |
| A2. 현지화 상세페이지 생성 | DTL-01-01 상세 페이지 | 확정 판매 정보, 분석 요약, 브랜드 톤 | 한국어 검수본 + 현지어 업로드본 (같은 구조), 품질 점수 | 잡 + 폴링 | gpt-4o 2~4회 |
| A3. 품질 검수 | (A2 내부) | 초안 | 0~100점, 지적 사항, 하드 컷 여부 | 순수 함수 | 없음 |
| A4. 텍스트 수정 재번역 | DTL-01-01 편집 패널 | 셀러가 고친 한국어 상품명·설명 | 현지어 상품명·설명 | 동기 | gpt-4o-mini 1회 |
| A5. 이미지 AI 생성 | DTL-01-02 이미지 생성 | 참고 사진, 생성 방식, 요청 문장 | 1024×1024 이미지 1장 | 잡 + 폴링 (20~40초) | gpt-image-1 1회 |
| A6. 부분 재실행 | EDT-01-01 상품 수정 | 바뀐 필드, 이전 분석 결과 | 시작 노드, 복원된 중간 산출물 | 분석 잡 내부 | 없음 |

공통 원칙
1. **숫자와 사실은 코드가, 문장은 LLM 이.** 사양 표 기본 행·breadcrumb·옵션 표기·가격·배송 문구는 확정 데이터에서 코드가 만든다. LLM 은 상품명·특징·본문만 쓴다.
2. **LLM 출력을 그대로 믿지 않는다.** 카테고리 id·속성 key·옵션 조합·현지어 구조를 코드가 다시 검증하고 고친다.
3. **사람이 확정한다 (HITL).** AI 값은 추천값이고, 셀러가 고친 값은 이후 AI 가 덮어쓰지 않는다.

## 2. A1. 판매 정보 추천 (R-003-12/13)

### 2-1. 데이터

`data/shopee_categories/{VN,SG,TH}.json` — Shopee 셀러센터 카테고리 트리를 수동 정리한 정적 스냅샷. 상품 등록 화면의 대분류 11종에 대응하는 leaf 43개.

| 필드 | 의미 |
|---|---|
| `id` | 국가 공통 slug. 판매 정보 저장·상세페이지의 참조 키 |
| `shopeeId` | 국가별 실제 category_id (셀러센터 확인 전 null) |
| `path` / `pathLocal` | 한국어 / 현지어 경로. breadcrumb 에 쓴다 |
| `appCategories` | 대응하는 상품 등록 대분류 |
| `keywords` | 후보 추리기용 단어 (한·영) |
| `attributes` | 속성 key 와 필수 여부. 라벨은 `attributeDefs` |
| `optionHints` | 옵션 이름·화면 라벨 후보 (예: 색상 / 제공 색상) |

### 2-2. 처리 절차

1. **후보 추리기 (코드).** 각 leaf 의 점수를 계산하고 상위 5개를 남긴다.

   `score(c) = 3 × [상품 대분류 ∈ c.appCategories] + 2 × |{ k ∈ c.keywords : k ⊂ 상품명·설명·셀링포인트·분석 키워드 }|`

   점수가 모두 0 이면 `other-general` (기타) 하나만 후보로 둔다. 셀러가 카테고리를 이미 골랐으면 그 하나만 후보다.
2. **선택과 채우기 (gpt-4o-mini).** 후보 목록(경로·속성·옵션 힌트)과 상품 정보를 주고 `SalesSuggestionDraft{category_id, attributes[], option1, option2, stock_hint}` 를 받는다. 프롬프트 규칙: 후보 밖 id 금지, 확인 안 되는 값은 빈 문자열, 제조국은 다른 정보가 없으면 "대한민국" (한국 셀러 역직구 전제), 캐릭터 색상은 "캐릭터명 (색상)".
3. **교정 (코드).**
   - 후보 밖 id 를 고르면 1순위 후보로 바꾸고, 그 응답의 속성·옵션은 **버린다** (다른 카테고리 기준으로 채운 값이므로).
   - 속성은 카테고리 스키마의 key 만 남기고 순서를 스키마 순서로 맞춘다. 빈 제조국은 "대한민국".
   - 옵션 이름이 힌트에 있으면 힌트의 라벨을 쓴다. 값은 공백·중복 제거 후 단당 최대 20개.
   - 2단만 있으면 1단으로 올린다. 옵션이 없으면 1단 힌트 이름만 채운 빈 옵션을 준다.
   - **조합 제한:** `|옵션1| × |옵션2| > 50` 이면 값이 많은 쪽부터 뒤에서 하나씩 덜어낸다.
4. LLM 이 실패하면(구조화 출력 실패·rate limit) 1순위 후보 + 빈 속성으로 응답한다. 화면은 항상 뜬다.

### 2-3. 저장 검증 (`validate_options`, Spring 도 같은 규칙)

2단만 있고 1단 없음 / 1단 값 0개 / 조합 50 초과 / 카테고리 미선택 → 422.

근거: `core/services/sales_suggest.py`, `core/catalog/shopee_categories.py`, `core/agents/prompts/sales_suggest.md`
검증: `tests/unit/test_sales_suggest.py` (18건)

## 3. A2. 현지화 상세페이지 생성 (R-003-06/11)

### 3-1. 흐름

```
START ─▶ draft_ko ─▶ culture_filter ─▶ quality_check ─┬─ 통과(≥70, 하드컷 없음) ─▶ localize ─▶ END
            ▲                                          ├─ 미달 & 재생성 < 2 ──┐
            └─────────────── 지적 사항 주입 ───────────┘                      │
                                                       └─ 미달 & 2회 소진 ─▶ localize (NEEDS_REVIEW)
```

| 단계 | 담당 | 진행 표시 (step / progress) |
|---|---|---|
| draft_ko | gpt-4o | DRAFT / 0.10 (+0.15 × 재생성 횟수) |
| culture_filter | 코드 | — |
| quality_check | 코드 (A3) | REVIEW / 0.55 |
| localize | gpt-4o + 코드 | LOCALIZE / 0.75 |

각 단계 진입 시 취소 요청을 확인한다.

### 3-2. 코드가 만드는 부분

- **사양 표 기본 행**: `카테고리`(경로) → 확정 속성 중 값이 있는 것(라벨은 카탈로그) → `무게` → `발송지: 대한민국` → `재고: N개`.
- **breadcrumb**: 한국어 `["홈", ...path]`, 현지어 `[homeLabel, ...pathLocal]`.
- **옵션 표기**: 판매 정보 옵션 1·2단의 짧은 이름과 값.
- 가격·배송·재고 문구(PdpContent 의 price/shipping/stockNote)는 Spring/dev_bff 가 판매 정보로 채운다. 언어별 템플릿 (예: vi `Miễn phí vận chuyển · Shopee SLS`, 가격 천 단위 마침표 `₫535.000`).

### 3-3. draft_ko (LLM)

입력: 국가·현지 지침, 상품 정보, 판매 정보(카테고리·옵션·가격·배송·재고), 사양 표, 분석 요약(포지셔닝·검색 키워드·강조 특징·리스크), 브랜드 톤, 수정 지시.
출력 `PdpCopyKo{name, usps[4], intro, features, benefits, call_to_action, extra_specs[≤3]}`.

- 첫 초안 temperature 0.2, 재생성 0.4. 재생성은 지적 사항이 달라 캐시하지 않는다.
- `extra_specs` 는 기본 행에 없는 라벨만, 최대 3개 덧붙인다.
- 본문 = 소개·특징·혜택·구매유도 4단락을 빈 줄로 잇는다.

### 3-4. culture_filter (코드)

`data/culture/common.yaml`(한국어 공통) + `data/culture/{cc}.yaml`(현지어·국가 금기)를 합친 사전에서 **`replace` 가 정해진 과장 표현만** 바로 바꾼다 (예: 최고의 → 만족스러운, 기적의 → 삭제). 하드 컷 표현은 건드리지 않고 A3 로 넘긴다 — 사람이 봐야 하는 표현을 기계가 조용히 지우지 않기 위해서다.

매칭 규칙: 영문은 단어 경계·대소문자 무시 (`cure` 는 `secure` 에 걸리지 않는다), 그 외 언어는 부분 문자열. 태국어는 띄어쓰기가 없어 세 글자 이상 구절만 사전에 넣는다.

| 사전 구분 | 처리 | 예 |
|---|---|---|
| banned | 하드 컷 | 치료·완치·FDA 승인(미확인)·짝퉁 / VN 남중국해 / TH 왕실·불상 / SG 할랄(미인증) |
| trademark | 하드 컷 | 샤넬·디즈니·산리오·포켓몬 등 타사 상표·캐릭터 |
| exaggeration | 감점, 일부 자동 치환 | 세계 최초·업계 1위·효과 100%·역대급 |

### 3-5. localize (LLM + 코드)

입력: 한국어본, 사양 표, 옵션, 현지 지침, 키워드. 출력 `PdpCopyLocal{name, usps, 4단락, specs[], options[]}`.

구조 보존 검증 (코드):
- 사양 표 행 수가 한국어본과 다르면 `MISSING_SECTION` 지적을 남긴다 (감점 없음, 검수자가 본다).
- 옵션값 개수가 한국어본과 다르면 현지어 옵션을 버리고 원문을 쓴다 — 재고 매트릭스와 어긋나면 주문이 깨진다.
- 현지어 텍스트에 사전을 다시 적용한다. 현지어 하드 컷이 있으면 `NEEDS_REVIEW`.

### 3-6. 결과 상태

`DONE` = 품질 통과 && 하드 컷 없음. 그 외 `NEEDS_REVIEW` — **미달이어도 결과는 준다.** 셀러가 편집 화면에서 고친다.

근거: `core/graph/content.py`, `core/content/culture.py`, `data/culture/*.yaml`, `core/agents/prompts/content_{draft,localize}.md`
검증: `tests/unit/test_content_graph.py` (12건), `tests/unit/test_dev_bff_flow.py`

## 4. A3. 품질 검수 (R-003-11)

순수 함수. 같은 입력이면 항상 같은 점수다.

`score = max(0, 100 − Σ 감점)`

| 항목 | 감점 | 하드 컷 | 조건 |
|---|---:|:---:|---|
| BANNED_WORD | 25 / 건 | ✓ | 사전 banned 매치 |
| TRADEMARK | 25 / 건 | ✓ | 사전 trademark 매치 |
| EXAGGERATION | 8 / 건 | | 사전 exaggeration 매치 |
| MISSING_SECTION — 상품명 없음 | 20 | | |
| MISSING_SECTION — 상품명 120자 초과 | 10 | | Shopee 상품명 상한 |
| MISSING_SECTION — USP 3개 미만 | 15 | | |
| MISSING_SECTION — 본문 4단락 미만 | 15 | | 소개·특징·혜택·구매유도 |
| MISSING_SECTION — 사양 표 5행 미만 | 10 | | |
| SEO_KEYWORD | 5 | | 분석 키워드가 상품명·USP·본문에 하나도 없음 |

같은 종류·같은 표현은 위치가 여러 곳이어도 한 번만 감점한다.
**통과 = score ≥ 70 && 하드 컷 없음.** 미달이면 각 지적의 `detail` 문장(예: "'아토피 개선' 표현을 빼세요 (의약품 오인 표현, 위치: sections[0])")을 다음 초안 프롬프트의 `revision` 에 넣는다. 재생성은 최대 2회 (초안 최대 3회).

근거: `core/content/quality.py` · 검증: `test_문제없는_초안은_만점이다`, `test_과장_표현은_감점만_한다`, `test_누락_섹션을_감점한다`, `test_검색_키워드가_없으면_감점한다`, `test_하드컷이면_지적사항을_넣어_다시_쓴다`, `test_2회_재생성해도_미달이면_검수필요로_결과를_준다`

## 5. A4. 텍스트 수정 재번역 (F-25)

셀러가 고친 한국어 상품명·설명은 **그대로 저장**한다 (AI 가 다듬지 않는다). 현지어본만 gpt-4o-mini 로 다시 옮기고 사전 치환을 적용한다. 기존 현지어본을 함께 넣어 브랜드 표기·문체를 맞춘다. 저장 후 `edited=true` 로 표시해 이후 재생성이 셀러 수정값을 덮어쓰지 않게 한다 (Spring 소유 규칙).

근거: `core/services/content_edit.py`, `core/agents/prompts/content_retranslate.md` · 검증: `test_셀러_수정본을_현지어로_다시_옮긴다`

## 6. A5. 이미지 AI 생성 (F-26·F-28)

### 6-1. 프롬프트 조립

`prompt = 대상 스타일(PRODUCT|DETAIL) + 생성 방식(BASIC|MODEL) + [모델 페르소나] + 가드레일 + "Seller request: " + 사용자 문장`

- 기본 모델 4종(20대 여성·동아시아 / 30대 남성·동아시아 / 20대 여성·동남아시아 / 30대 남성·동남아시아)은 `data/models.yaml` 의 가상 인물 묘사 문장이다. 실존 인물을 지칭하지 않는다.
- 가드레일: 참고 사진의 형태·색·비율·인쇄 디테일 유지, 요청 없는 글자·워터마크·타사 로고 금지, 사실적 사진.

### 6-2. 처리 절차

1. 캐시 키 `sha256(모델 파일 버전, fake 여부, prompt, 참고 사진 URL 정렬)` 의 파일이 있으면 즉시 반환 (리허설·재시연).
2. 일일 상한 확인: Redis `ai:image_budget:{YYYYMMDD}` 증가, Redis 가 없으면 프로세스 카운터. `DAILY_IMAGE_BUDGET` 초과 시 `DAILY_BUDGET_EXCEEDED`.
3. 참고 사진 최대 4장을 읽는다 (업로드 파일 · data URI · http). 못 읽은 사진은 건너뛴다.
4. 참고 사진이 있으면 `images.edit`(다중 입력), 없으면 `images.generate`. 1024×1024.
5. 호출 직후 취소를 다시 확인하고, 취소됐으면 저장하지 않는다.
6. 이미지 잡은 취소 요청 시 태스크를 즉시 끊는다. 대기 중이면 시작 전에 멈춘다.

FakeLLM 모드(키 없음)는 API 를 부르지 않고 첫 참고 사진을 결과로 복사한다 (비용 0, 화면 흐름 검증용).

근거: `core/services/image_gen.py`, `data/models.yaml`, `core/jobs/runner.py` · 검증: `tests/unit/test_image_gen.py` (8건)

## 7. A6. 부분 재실행 (R-000-05)

### 7-1. 시작 노드 판정

`start = argmin_{f ∈ changedFields} order(FIELD_START[f])` (접두사로 찾고, 모르는 필드는 처음부터)

| 바뀐 필드 | 시작 노드 | 다시 부르는 LLM |
|---|---|---|
| 상품명·카테고리·설명·셀링포인트·타겟·이미지 | PRODUCT_UNDERSTANDING (처음부터) | 전부 |
| marketProfile.* (브랜드 톤 등) | MARKET_INSIGHT | 인사이트·마진 해설·종합 결론 |
| 무게·포장 | LOGISTICS_ESTIMATE | 마진 해설·종합 결론 |
| 원가·목표 마진·고정비·배송 방식 | MARGIN | 마진 해설·종합 결론 |

### 7-2. 복원

시작 노드 앞 노드들의 산출물(`product_features, customs, market_raw, scores, competition, insight, logistics …`)을 이전 결과(`previousResult`)에서 꺼내 국가 state 에 넣고, 국가 서브그래프 입구의 조건 분기가 시작 노드로 바로 들어간다. 진행률은 복원한 노드 수만큼 미리 채운다.

예외 규칙 — 틀린 결과보다 느린 결과가 낫다:
- 필요한 값이 하나라도 없거나 이전 결과 형식이 깨졌으면 → 처음부터.
- 이전에 실패한 국가 → 처음부터.
- 통관에서 막힌 국가이고 시작 노드가 통관 뒤 → 이전 결과를 그대로 유지 (다시 돌리지 않음).
- 이전 결과에 없는 국가(새로 추가) → 처음부터.
- 진입점수·순위는 REPORT_COMPOSE 가 항상 다시 계산한다.

근거: `core/graph/rerun_map.py`, `core/graph/analysis.py` · 검증: `tests/unit/test_partial_rerun.py` (8건)
